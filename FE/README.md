# MyWorkspace 프론트엔드

Lovable에서 검토한 파스텔 블루 화면을 React·TypeScript·Vite 정적 앱으로 구성했습니다. 메인, 캘린더, 서버 대시보드, WOL, 로그인 화면을 제공합니다.

## 실행과 검증

Node.js 22.12 이상인 22.x 버전을 사용합니다.

```sh
npm ci
npm run build
npm run typecheck
npm test
npm run lint
npm run dev
```

빌드 결과는 `dist/`입니다. 운영 시 Nginx에서 정적 파일을 제공하고, 페이지 직접 접속을 위해 `try_files $uri $uri/ /index.html;`을 설정합니다. `vite preview`는 로컬 확인용입니다.

200번 LXC의 Nginx에 배포했습니다. 실제 REST API가 기본이며 실행과 갱신 절차는 [운영 문서](../docs/backend-operations.md)를 참고하세요. 백엔드 없이 시안만 실행하려면 `VITE_API_MODE=mock npm run dev`를 사용합니다. 단위 테스트는 시안 API를 사용합니다.

## 실제 서비스와 시안의 구분

- 기본 모드는 서버의 실제 비밀번호 세션과 네트워크 자동 입장 정책을 사용합니다. 쓰기 요청은 CSRF 토큰을 전송합니다.
- 일정·시간표·PC 목록은 MySQL에 저장합니다. 이전 시안의 브라우저 자료는 메뉴에서 선택해 가져올 수 있습니다.
- Proxmox 상태와 기록은 실제 데이터이며 WOL은 실제 매직 패킷을 전송합니다. 부팅 여부를 확인하지 못하면 미확인으로 표시합니다.
- iCloud는 아직 연결하지 않았으며 설정에 미연결 상태를 표시합니다. 현재 일정은 서버에만 저장합니다.
- `mock` 모드에서만 `demo` 비밀번호·브라우저 저장·가상 서버 상태를 사용합니다. 이 코드는 운영 번들에서 제외됩니다.
- 날짜와 시간은 브라우저 설정과 관계없이 Asia/Seoul을 사용합니다.
- 실제 접근 제어와 MySQL 저장은 Spring Boot가 담당합니다. iCloud 계정 동기화는 추후 연동합니다.

`src/api/client.ts`는 화면의 API 계약, `src/api/restApi.ts`는 실제 서버 구현, `src/api/mock/`은 시안·테스트 구현입니다.

## 메인·서버·WOL

- 메인: 날짜를 시계 위에 표시하고 오전·오후 12시간제로 초까지 표시합니다. 오전·오후는 숫자 크기의 50%이며 화면 너비에 맞춰 시계 전체가 줄어듭니다. 미니 달력에서 날짜를 선택하면 이동 없이 `2026년 11월 6일 금요일의 일정` 형태의 제목과 해당 날짜의 일정·수업을 표시합니다.
- 서버: 호스트는 CPU·RAM·네트워크 3열 그래프입니다. CPU 온도는 코어 수 옆에 표시합니다. VM·LXC는 최대 두 열의 카드이며 각 카드에 CPU·RAM·네트워크·디스크 2×2 그래프가 있습니다. 모바일 카드는 한 열입니다. 호스트와 게스트의 `1m / 15m / 1D / 1W / 1M` 선택은 독립적이며 게스트 선택은 모든 게스트 그래프에 적용합니다. 스토리지 바는 유지합니다.
- 네트워크는 Input·Output 두 선을 같은 축에 표시하며 단위는 B/s·KB/s·MB/s입니다. CPU/RAM/디스크의 백분율 축과 달리 네트워크는 데이터에 맞춰 축을 조정합니다. 게스트 RAM과 디스크는 사용률과 사용량/전체 용량을 함께 표시합니다. 디스크 사용량을 얻을 수 없는 경우에는 미지원으로 표시하며 0% 기록을 만들지 않습니다.
- 서버 현황·기록은 페이지가 활성화된 동안 60초마다 조회합니다. 실제 Proxmox 기록을 사용합니다. `1m`은 5초, `15m`은 1분, `1D`는 15분, `1W`는 1시간, `1M`은 6시간 간격이며 `1M`은 최근 30일입니다. 배포 전 기록은 생성하지 않습니다. 프론트 조회 주기와 서버의 약 5초 수집 간격은 별개입니다.
- WOL: 최대 두 열의 큰 버튼과 ‘WOL 리스트 수정’ 모달을 제공합니다. 이름·MAC 수정과 PC 추가·삭제는 전체 목록으로 저장합니다. 빈 MAC은 미등록 상태이며 중복·잘못된 MAC은 저장하지 않습니다. 실패 시 초안과 기존 목록을 유지하고 실제 전송과 부팅 미확인을 구분합니다.
- 모바일: 왼쪽 버튼에서 화면에 고정된 메뉴 패널을 열고 스크롤 없이 페이지를 선택합니다. 일정 모달의 날짜·시간 입력을 화면 너비에 맞추고 시간 입력은 한 열로 표시합니다.

## 캘린더 편집

날짜 칸의 일정은 클릭해도 수정 모달을 열지 않고 그 날짜를 선택합니다. 일정 수정은 선택 날짜 아래의 일정 목록에서 합니다. ‘일정 추가’ 버튼은 선택 날짜 제목 아래 하나만 표시하며, 날짜 더블클릭도 같은 모달을 엽니다. 모달은 일반 일정으로 시작하고 ‘종일’ 토글로 전환합니다.

별도 ‘내 일정(로컬)’ 분류와 종일 빠른 추가 모달·안내 문구를 제거했습니다. 이전 시안에서 로컬 분류로 저장한 일정은 내용·ID를 보존해 iCloud 시안 분류에서 계속 표시·수정합니다. 이 호환 처리는 실제 iCloud 계정에 전송하지 않습니다.

공휴일은 체크박스 없이 항상 표시하고, 다른 캘린더를 숨겨도 이름과 빨간 날짜를 유지합니다. 일정이 많은 날에도 공휴일 이름은 생략하지 않으며 오늘·토요일·옆 달 공휴일도 빨간색으로 표시합니다. 실제 모드에서는 서버가 가져온 한국 공휴일 피드를 사용하고 조회·갱신 장애를 표시합니다.

## 시간표 편집

캘린더의 ‘시간표 설정’에서 요일·시간 표를 편집합니다. 빈 칸을 누르면 수업을 추가하고, 수업 블록이나 ‘편집할 수업’ 목록에서 선택해 과목명·강의실·교수명·요일·시작/종료·휴강일을 수정합니다. ‘시간표 저장’이 전체 초안을 저장하며 취소하면 폐기합니다. 키보드로는 ‘수업 추가’와 수업 선택 목록을 사용할 수 있습니다.

30분 칸에서 추가한 뒤 시·분 선택에서 `18:25–19:15`처럼 5분 간격으로 조정할 수 있습니다. 기존에 저장한 5분 간격 밖 시각은 자동 반올림하지 않고 그대로 표시합니다. 같은 요일의 겹치는 수업은 저장하지 않으며, 주말·기본 표시 시간 밖 수업은 표를 자동 확장합니다. 교수명 필드가 없는 기존 브라우저 저장 데이터도 그대로 읽습니다.

Firecrawl로 [FullCalendar의 TimeGrid](https://fullcalendar.io/docs/timegrid-view)와 [MDN의 CSS Grid 줄 배치](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Line-based_placement)를 검토했습니다. 고정 요일 시간표에는 기존 React 구성과 CSS Grid를 사용해 별도 달력 라이브러리 없이 분 단위로 수업을 배치했습니다. 드래그 이동·이미지 자동 인식은 이번 범위에 포함하지 않습니다.
