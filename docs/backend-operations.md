# 사용과 검증

이 저장소에는 기능 사용법과 개발 검증 결과를 기록합니다. 실제 접속 주소·운영 계정·비밀정보 위치·복구 자료는 비공개 운영 기록으로 관리합니다.

## 캘린더와 시간표

일정 추가·수정에서 시작·종료를 5분 간격으로 선택할 수 있습니다. 달력과 날짜별 목록은 개인/iCloud 일정을 수업보다 먼저 보여줍니다.

시간표 설정에서 과목을 선택한 뒤 ‘시간 추가’를 누르면 같은 수업에 여러 시간을 등록할 수 있습니다. 과목명·교수명은 공유하며 각 시간의 휴강일과 강의실은 따로 관리합니다. 기존에 동일한 정보로 나눠 입력한 수업은 설정 초안에서 묶어 표시합니다. 저장하기 전에는 원본을 바꾸지 않습니다.

## 암호와 OTP

HTTPS 사이트의 왼쪽 아래 ‘설정’에서 비밀번호 변경을 선택합니다. 기존 비밀번호 또는 등록한 Google OTP를 선택해 새 비밀번호와 확인 값을 입력합니다.

Google OTP를 처음 사용할 때는 기존 비밀번호를 확인한 후 앱에 QR이나 설정 키를 등록하고 첫 인증번호를 확인합니다. 등록 완료 후 사용할 수 있습니다. OTP 해제도 본인 확인이 필요합니다. 계정 비밀값을 채팅이나 저장소로 공유하지 않습니다.

## iCloud

캘린더의 iCloud 설정에서 Apple ID·앱 전용 암호로 캘린더를 선택합니다. 일반 일정은 편집하며 반복·여러 날·초대 일정은 조회합니다. 기존 서버 일정은 자동 업로드하지 않습니다.

## 검증

- 백엔드 테스트 21개·프론트엔드 테스트 71개 통과.
- 분할 수업·휴강일·겹침 검사와 비밀번호·OTP 본인 확인 동작을 통합 테스트로 확인.
- PC·모바일 화면의 표시 순서·5분 입력·설정 진입·QR 생성 확인.
- 사용자 보안 설정은 실제로 바꾸지 않고 화면의 민감한 변경 요청을 모의 응답으로 검증.
- 배포 후 기본 상태와 백업의 별도 복원 검증 완료.
- 로컬 JavaScript 도구의 네이티브 종료가 발생한 검사는 최적화 비활성 상태로 완료. 최종 린트 오류는 없으며 기존 경고 2개가 남음.

실제 휴대폰 Authenticator 등록과 Safari 실기기는 미검증입니다.

## 이전 시안 정리

기존 데이터 가져오기 메뉴·모달·API는 제거했습니다. 이미 적용된 과거 스키마 변경 기록은 유지합니다. 페이지 시작 시 해당 주소에 남은 이전 시안 데이터와 가져오기 완료 표시를 삭제하며, 현재 서버 자료와 관련 없는 브라우저 설정은 유지합니다. 사용하던 주소별로 새 페이지를 열면 정리됩니다.

## WOL 결과 표시

WOL은 패킷 전송 결과·시각만 표시하며 부팅 확인 API와 화면의 반복 조회는 제거했습니다. 저장한 MAC 주소로 보내는 동작과 서버의 10초 재요청 제한은 유지합니다. 전송 완료는 PC 부팅을 보장하지 않습니다.

## 접속 경로와 자동 입장

내부망 주소로 접속할 때와 도메인으로 접속할 때는 서버에 보이는 IP가 다를 수 있습니다. 자동 입장 목록에는 내부망과 확인한 집 공인 IP, 허용한 Tailscale 기기의 정확한 주소를 별도로 등록합니다. 프록시의 접속 허용 목록에 있는 학교·기타 외부 주소는 비밀번호 로그인을 유지합니다.

프록시는 실제 접속 IP를 덮어써 전달하고 앱 앞단은 지정한 프록시에서 온 헤더만 신뢰합니다. 전달 IP 누락·형식 오류·외부 요청의 헤더 위조는 자동 입장을 허용하지 않습니다.

Tailscale에서는 도메인용 내부 DNS를 사용해 프록시 내부 주소로 연결해야 VPN 경로가 적용됩니다. 클라이언트의 Tailscale DNS 사용이 꺼져 있거나 브라우저의 별도 DNS 설정이 이를 우회하면 공개 인터넷 경로로 접속할 수 있습니다. VPN을 켰다는 사실만으로 인터넷 경로의 접속을 인증하지 않습니다. 집 공인 IP나 허용 기기가 바뀌면 자동 입장 목록도 갱신해야 합니다.

운영 설정을 반영한 후 새 브라우저의 PC·모바일에서 도메인 자동 입장과 HTTPS 안내 주소를 확인했습니다. 지정 IP·IPv6 허용, 미등록 VPN·학교·외부 주소와 전달 헤더 위조 차단, VPN용 도메인의 내부 DNS 응답을 확인했습니다. 실제 원격 VPN 기기의 재접속은 별도 확인이 필요합니다. 실제 주소와 허용 목록은 비공개 운영 설정으로 관리합니다.

### WOL 전송과 재시도

PC 목록 잠금으로 저장 MAC과 10초 쿨다운을 읽고 예약을 DB에 커밋한 뒤 UDP 패킷을 전송합니다. 예약 저장/커밋 실패 시 패킷을 보내지 않습니다. 전송 오류도 전달 여부가 불확실할 수 있으므로 예약을 유지하고 10초 뒤 다시 요청할 수 있습니다. 예약 후 MAC 변경은 다음 예약부터 적용됩니다.

### 배포 실패 복구

신규 JAR·FE를 root 전용 임시 디렉터리에 준비하고 Nginx 설정을 검사한 뒤 버전을 전환합니다. 이전 JAR·FE 링크와 Nginx·systemd 설정, 서비스 실행/자동 시작 상태를 기록합니다. 전환 중 오류가 나면 이 구성을 함께 복구하고 이전 백엔드의 기동을 확인합니다. 복구 자체가 실패하면 예외에 표시된 임시 디렉터리에 설정 백업을 남깁니다. `python3 -m unittest discover -s BE/deploy`로 운영 서버 접속 없이 실패 단계별 복구를 검증합니다.
